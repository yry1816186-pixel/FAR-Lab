## 1. End-to-end stage map

Owner chain (all in `launch_scientist.py` unless noted):

1. **Idea generation** — `generate_ideas()` from `ai_scientist/generate_ideas.py:76`, called at `launch_scientist.py:343`. Reads template `prompt.json` + `seed_ideas.json` + `experiment.py` source; produces up to `--num-ideas` (default 50) ideas, each with reflection rounds (`NUM_REFLECTIONS = 3`, `launch_scientist.py:22`).
2. **Novelty check** — `check_idea_novelty()` `generate_ideas.py:405`, called `launch_scientist.py:352`. Agentic search loop vs Semantic Scholar (or OpenAlex, `--engine`). Writes `novel` bool back into `ideas.json`; only `novel==True` ideas proceed (`launch_scientist.py:363`).
3. **Experiment** — per idea, `do_idea()` `launch_scientist.py:154` copies template to timestamped results folder, seeds `notes.txt` with baseline, then `perform_experiments()` `perform_experiments.py:116` runs an aider Coder loop: edit `experiment.py` → subprocess `python experiment.py --out_dir=run_N` → feed results/errors back, max 5 runs / 4 fix-iters; then `plot.py` loop; then verbose `notes.txt` update.
4. **Writeup** — `perform_writeup()` `perform_writeup.py:401` (called `launch_scientist.py:254`): fresh aider Coder on `latex/template.tex`; section-by-section write + refine, Related Work sketch, up to 20 citation rounds via Semantic Scholar tool-use, second full refinement pass, then `generate_latex()` deterministic checks + `chktex` fix loop + pdflatex/bibtex compile.
5. **Review** — `perform_review()` `perform_review.py:126`, called `launch_scientist.py:268` with **hard-coded reviewer model gpt-4o-2024-05-13, num_reflections=5, num_fs_examples=1, num_reviews_ensemble=5, temperature=0.1** (`launch_scientist.py:270-275`). Review JSON saved to `review.txt`.
6. **Improvement (optional)** — `perform_improvement(review, coder)` `perform_review.py:386` + re-compile + re-review into `review_improved.txt` (`launch_scientist.py:285-308`).

Parallelism: multiprocess queue of novel ideas, one worker per GPU, CUDA_VISIBLE_DEVICES pinning, and a deliberate 150 s stagger between worker starts to avoid correlated API bursts (`launch_scientist.py:366-391`). Per-idea `log.txt` captures stdout/stderr via fd swap (`launch_scientist.py:186-192, 313-318`).

## 3. Deep dives

### 3.1 Ideation loop (`generate_ideas.py`)

Two loops exist. **Batch mode** (`generate_ideas`, L76): template provides `prompt.json` (persona + task description derived from the base paper's abstract), `seed_ideas.json` (2-3 human seed ideas in the same JSON schema), and the full source of `experiment.py`. Seeds are serialized into an `idea_str_archive` (L99-102). Then `max_num_generations` times: a first prompt embeds task description + code + **the JSON dump of every idea so far** and asks for one new differentiated idea; then up to `num_reflections-1` reflection rounds refine that single idea in a continuing msg history, with the "I am done" early-stop sentinel (L157-159). So "multi-round diversity" = *between*-idea diversity via the growing conditioning archive, plus *within*-idea refinement via reflection — not a population/pareto mechanism. Failures are caught per-idea and skipped (L162-164). **Open-ended mode** (`generate_next_idea`, L178): same machinery one idea at a time, but completed ideas carry a reviewer "Score" appended to the archive prompt (L221-225), closing the generate→experiment→review→generate loop (`experimental/launch_oe_scientist.py`).

Weaknesses worth not inheriting: unbounded archive context; novelty is a single binary field with no overlap citation recorded; reflection may just paraphrase.

### 3.2 Novelty check (`check_idea_novelty`, L405-492)

Per idea: multi-round agentic loop (≤10). Each round the model gets the idea + last query results and must output a JSON `Query` or declare a decision in its thoughts ("Decision made: novel/not novel", matched case-insensitively as substring, L448-454). Queries hit Semantic Scholar graph API (top 10, title/authors/venue/year/citationCount/abstract) or OpenAlex with normalization; 1 s sleep between calls; exponential backoff on HTTP errors. Any exception in a round is printed and the round is skipped (loop continues, L481-483) — meaning a persistently failing API silently consumes rounds and the idea stays `novel=False` (fail-closed). Already-checked ideas are skipped (idempotent resume), and `ideas.json` is rewritten after each idea. Only novelty-gated ideas proceed to expensive stages.

### 3.3 Auto-reviewer (`perform_review.py`)

Pipeline: base prompt = NeurIPS review form (anchored 1-4 subscales + 1-10 Overall + 1-5 Confidence + binary Accept/Reject decision, no borderline labels) + optional few-shot paper/review pairs (real ML conference reviews, cached .txt) + the paper text (PDF→markdown). With `num_reviews_ensemble>1` (5 in production): one request with `n=5` at temp 0.75 (seeded), parse each, drop unparseables, an Area-Chair meta-prompt synthesizes a consensus review, and **all numeric fields are then overwritten by the rounded mean of the ensemble members' in-range scores** (L177-192); if the AC fails, the first parsed review is used (L173-174). Message history is then rewritten to look like the aggregated review was "the" assistant output (L194-209) so reflection continues from the aggregate. Then ≤5 reflection rounds re-critique the review with early stop. Default persona is the *pessimistic* reviewer (unsure → reject), L18-25, 136. This exact stack is what `iclr_analysis.py` validated on 500 ICLR papers (ensemble=5, reflections=5, temp=0.1, 0-shot was the reported-best config, L2), yielding the paper's near-human agreement claims.

Key aggregation insight for FAR-Lab: consensus = LLM meta-synthesis for text fields + deterministic mean for numeric fields, with range validation per field and graceful degradation — a clean split of semantic vs deterministic responsibility.

### 3.4 Experiment loop & error handling (`perform_experiments.py`)

aider Coder owns file edits (diff edit format, no git, auto-yes). The orchestration contract: agent edits code, system runs the frozen command `python experiment.py --out_dir=run_N` in a subprocess (7200 s timeout), reads `final_info.json`, and returns either the aggregated means ("Decide if you need to re-plan…") or the tail-1500-chars of stderr ("Run failed with the following error …") as the next agent prompt. Budgets: ≤5 successful runs, ≤4 consecutive failed fix iterations (counter resets on success); exhausting fix-iters fails the whole idea (returns False → no writeup). Partial output dirs from failed runs are deleted; every run's code state is snapshotted as `run_N.py`. A sentinel string "ALL_COMPLETED" from the agent ends the loop early. Same pattern for `plot.py` (600 s timeout, ≤4 fixes). Finally the agent is made to write verbose `notes.txt` entries explicitly for the downstream writeup agent.

Latent defect worth noting: L139's post-loop failure check reads `current_iter >= MAX_ITERS` — correct only because the loop breaks under the same condition; the success/failure accounting depends on subtle counter resets, a fragility FAR-Lab should avoid by making budgets explicit state.

### 3.5 Writeup & deterministic hygiene (`perform_writeup.py`)

Section pipeline: Title+Abstract → six core sections (each write followed immediately by a criticize-and-refine pass with a fixed error checklist) → Related Work sketched in LaTeX comments only → up to 20 citation rounds (two-step query/select tool-use; bibtex spliced programmatically before `\end{filecontents}`; agent then told the bib was already updated, with an explicit do-not-re-add guard) → Related Work refine → second full refinement pass over all 8 sections (redundancy/space focused) → `generate_latex`. `generate_latex` is the hygiene gem: regex checks for citations missing from the bib, figures missing from disk, duplicate figures, duplicate section headers — each generating a targeted minimal-fix prompt; then ≤5 chktex-lint fix rounds (four warning classes suppressed as noise); then pdflatex→bibtex→pdflatex×2 with 30 s per-command timeout. All checks are deterministic-first, LLM-second, and each targets one precise defect.

### 3.6 Cost accounting — absent

This checkout contains **no token/cost instrumentation** (verified by grep, exit 1 on all cost identifiers). The famous per-stage cost table from the paper is not reproducible from this code state. Only an anecdotal README figure (≈<$15/paper with Claude 3.5 Sonnet, README:346-348). If FAR-Lab wants per-stage cost telemetry, it must build it; nothing to port here.

## 5. Rejection notes (looked at, deliberately not recommended)

- **M12 JSON-extraction repair chain** (`llm.py:289-314`): FAR-Lab is zod-only with typed pipelines; tiered regex repair is strictly inferior. Reject.
- **M9 NeurIPS rubric dimensions per se**: paper-review-specific (Originality/Quality/Clarity 1-4…); FAR-Lab's scientific rubric (falsifiability, evidence alignment) is domain-correct. Keep only the *anchored-scale* design principle. Reject as-is.
- **M24 few-shot .txt cache**: trivial micro-optimization; FAR-Lab caching should be at retrieve/evidence layer. Reject.
- **Substring sentinel detection** ("I am done", "Decision made:", "ALL_COMPLETED" — `generate_ideas.py:157,448`; `perform_experiments.py:132`): brittle control-plane-over-prose; FAR-Lab should use structured output fields instead. Reject pattern, keep the early-stop concept (M3).
- **Silent round-skip on exception in novelty loop** (`generate_ideas.py:481-483`): prints and continues, which converts API outages into false "not novel" verdicts without any error state on the idea. Anti-pattern for FAR-Lab's fail-visible principle. Reject.
- **Aider-coupled editing**: the whole writeup/experiment stage assumes in-place file editing by a coding agent; FAR-Lab is TS/zod typed-stage architecture — mechanism (edit-fix loop) portable, integration is not. Reject integration.
- **Cost table**: does not exist in this checkout (M14). Nothing to port; flagged as a FAR-Lab gap-check instead.
- **Unbounded prev-ideas archive**: known context bomb at 50+ ideas; do not copy verbatim-JSON conditioning; use hashed/clustered digests.
