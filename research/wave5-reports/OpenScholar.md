## 1. Data-flow map (search → rerank → synthesize → cite → verify)

Canonical one-query flow, reconstructed from `OpenScholar.run()` (`src/open_scholar.py:606-715`) and `run.py:226-255`:

1. **Candidate collection (offline + online)**
   - Offline dense: Contriever-variant encoder (`akariasai/pes2o_contriever`, `retriever/ric/conf/pes2o_v3.yaml`) over peS2o v3, 45M papers → 200M+ passage embeddings, 16 shards, FAISS flat-IP (or PQ) index; passages chunked at **256 words** (`retriever/src/data.py:182-194`, `conf` `chunk_size: 256`); each hit also returns the **next chunk** (`retrieval next text`, `retriever/src/search.py:124`). Default offline depth `n_docs=100` (retriever README; `conf/default.yaml` `n_docs: 1000` for scaling runs).
   - Multi-source merge: per-source result files concatenated, re-sorted by raw retrieval score, truncated to n_docs (`post_hoc_merge_topk_multi_domain`, `retriever/src/search.py:388-465`). Then MinHash dedup (below). Final cross-source ordering is effectively re-decided by the downstream reranker.
   - Online APIs (`src/use_search_apis.py`, invoked by `--use_google --you_search --use_semantic_scholar`):
     - **Semantic Scholar**: LLM turns the query into ≤3–5 short search strings (`keyword_extraction_prompt`, `use_search_apis.py:24-35`, `src/open_scholar.py:142-170`); each string hits `/graph/v1/paper/search` with `minCitationCount=10, sort=citationCount:desc, limit=10` (`use_search_apis.py:96-119`); dedup by `paperId`; abstract used as text; if the paper has an ArXiv id, **full-text paragraphs are scraped from ar5iv HTML** (sections `S\d+`, paragraphs `ltx_para`, `use_search_apis.py:207-246`).
     - **Google / you.com**: site-restricted search `site:arxiv.org OR site:pubmed...` → extract arxiv/pubmed ids → ar5iv full-text paragraphs + S2 batch metadata (`use_search_apis.py:279-384`), PubMed efetch XML abstracts (`:248-276`), S2 `/paper/batch` for citationCount/title/url (`:174-205`).
     - All appended: `item["ctxs"] += retrieved_passages` (`use_search_apis.py:513`).
   - **Dedup (two layers)**: (a) near-dup via MinHash LSH, 13-word shingles, Jaccard ≥0.8 removed, 128 perms, multiprocess; **the query text itself is hashed first so contaminated/echo passages get dropped** (`retriever/utils/deduplication.py:28-90`, wired at `search.py:473-481`); (b) exact-prefix dedup keyed on `text[:100]+title` at inference time (`src/open_scholar.py:679, 759`). Short chunks (<13 w / <12 w) dropped (`deduplication.py:53`, `search.py:563-568`).
2. **Rerank + candidate shaping** (`src/open_scholar.py`)
   - Cross-encoder rerank: BGE-reranker-large fine-tune (`OpenScholar/OpenScholar_Reranker`) via FlagReranker, scoring `title + abstract? + text` per passage against the query (`open_scholar.py:40-65`, `run.py:210-214`).
   - Optional priors: `min_citation` filter (drop low-cited papers **only if enough remain above threshold**, `open_scholar.py:122-126`); `norm_cite` adds `citationCount/maxCitation` to the rerank score (`:53-58`); `max_per_paper` caps passages per paper title, enforcing source diversity in context (`:616-630`).
   - A listwise LLM rerank path (1–5 rating rubric with explanations, `instructions.py:106-117`; parser `open_scholar.py:116-118`) exists but the shipped default is the cross-encoder.
3. **Context assembly** — `top_n` (default 10) passages serialized as `[i] Title: {t} Text: {x}` lines (`open_scholar.py:190-196`); citations like `[3]` are **stripped from retrieved passage text** first so source numbering can't collide with context numbering (`remove_citations`/`process_paragraph`, `:37-38, 717-720`). Prompt = task instruction + 1-shot demonstration (example references + cited answer) + `References:` + numbered passages + question (`instructions.py:80-104`). No token budget, no explicit ordering policy beyond reranker score, no truncation beyond count-based cuts.
4. **Synthesis + self-feedback loop** (`open_scholar.py:606-715`, the "Open Retriever Self-reflective Generation" pipeline, README:95-107)
   - Generate answer (temp 0.7, `[Response_Start]/[Response_End]` markers; strip any model-hallucinated "References:" section, `:251-253, 713-714`).
   - `get_feedback`: model critiques its own answer, returns ≤3 prioritized feedbacks; each feedback may carry a **self-contained follow-up search question** (`Feedback: ... Question: ...` regex, `:257-260`; prompt `instructions.py:174-191`).
   - No-question feedback → `edit_with_feedback` (rewrite with same references, `:294-327`).
   - Question-bearing feedback → corrective retrieval: keyword extraction on the question → S2 search → dedup → supplemental cross-encoder rerank → `edit_with_feedback_retrieval` rewrites the answer **adding new passages with citation numbers offset to continue the existing numbering** (`passage_start_index=len(ctxs)`, `:329-335, 657-700`).
   - **Regression guard**: edited answer accepted only if `len(edited)/len(orig) > 0.9` (else "skipping as edited answers got too short", `:651-655, 689-700`) — prevents the model from deleting content under edit pressure.
5. **Citation presentation / post-hoc attribution** (`insert_attributions_posthoc_paragraph_all`, `open_scholar.py:527-604`)
   - Splits output into paragraphs, finds citation-worthy paragraphs lacking `[n]` markers, sends each (with the full reference list) to the LLM with prompt `instructions.py:239-258`: **insert citation only where fully supported by a reference; if none supports it, leave the sentence uncited**. So uncited statements are allowed to survive as explicit uncertainty rather than being force-cited.
   - Citation-support judging prompt (Yes/No full-support rating + explanation, `instructions.py:282-301`) ships here but its metric harness is in ScholarQABench.
6. **Telemetry/state**: per-query OpenAI cost accounting (word-count approximation, `open_scholar.py:16-35`), latency per query, checkpoint every 10 items + resume-from-existing-output (`run.py:163-168, 246-248, 250-252`); retriever service logs every query (`retriever/api/serve_pes2o.py:62-76`).

## 3. Deep dives

### 3.1 The self-feedback loop is content-gap-driven, not citation-verification-driven
Despite the "corrective RAG" framing often attached to OpenScholar, in the shipped code the re-search trigger is a **self-critique about missing content** ("Only one limitation discussed is efficiency. Question: What are the disadvantages of retrieval-augmented LMs?"), not a failed citation check. The feedback prompt (`instructions.py:174-191`) explicitly instructs: feedback needing literature ⇒ attach a *self-contained* question; stylistic feedback ⇒ no question. The loop caps at 3 feedbacks (`open_scholar.py:641-644`). Citation *quality* is instead addressed after the fact by the post-hoc attribution pass (mechanism #1) — the two mechanisms are orthogonal: gap-filling loop grows coverage; post-hoc pass enforces "cite only what supports". For FAR-Lab this decomposition (coverage loop ⊥ grounding gate) maps cleanly onto `feedback → revise` vs `verify (fail-closed)` staying separate stages, which FAR-Lab already does architecturally; the borrowable part is the *structured gap question* as the hand-off artifact between stages.

### 3.2 Context assembly is count-based, not budget-based
`top_n` (default 10; CLI `run.py:117`) passages, each a 256-word chunk (optionally with title, and abstract only used for reranking, not generation, unless `use_abstract` in rerank text `open_scholar.py:42-45`). There is **no token accounting anywhere in `src/`** — the only budget-ish control is `max_tokens` for generation output (`run.py:120`). Cost estimation uses `len(text.split(" "))` as a token proxy (`open_scholar.py:239`). Consequences for FAR-Lab B5/B6: OpenScholar offers no solved answer to context-budget packing; its usable ideas are the *diversity cap* (#3) and *next-chunk* (#8), both composable with FAR-Lab's token-budgeted packer. The 1-shot demonstration with a fully-worked cited example (`instructions.py:80-104`) is their strongest context-engineering artifact — it pins the citation format behavior for arbitrary (model-agnostic) generators.

### 3.3 Engineering defects observed (evidence for "port ideas, not code")
- Silent error swallowing throughout API layer: bare `except: return None` (`use_search_apis.py:51-52, 75-76, 135-137`), which violates FAR-Lab fail-visible policy.
- `get_paper_data` defined twice; second definition shadows first (`use_search_apis.py:37, 58`).
- Field bug: `"year": paper_list[paper_id]["title"]` (`use_search_apis.py:167, 171`) — year actually holds the title.
- You.com key referenced as undefined `YOUR_API_KEY` global (`use_search_apis.py:329`) though README says to export it — env-name mismatch.
- Hard-coded cluster paths (`pes2o_ds.py:52`, `serve_pes2o.py:63`, `passage_utils.py:66-69`).
- Fragile regex postprocessing: feedback regex depends on trailing `\n` (`open_scholar.py:258`); citation-strip regex mangles text containing legitimate brackets (`:37-38`).
- Merge asserts `len(ctxs)==n_docs` (`search.py:369`) — brittle against short result lists.
None of these are surprising for research code; they reinforce treating the repo as a mechanism catalog, not a dependency.

## 4. Top-8 ranked (by FAR-Lab leverage)

1. **Post-hoc attribution insertion with permission-to-stay-uncited** (`open_scholar.py:527-604`, `instructions.py:239-258`) — C4/C5: finish-then-anchor pass; unsupported sentences stay uncited. Directly complements FAR-Lab fail-closed verify; low port cost; high presentational payoff.
2. **Structured gap-question feedback loop with offset-numbered supplemental retrieval** (`open_scholar.py:639-700`, `instructions.py:174-216, 303-320`) — J1/B6: critique → self-contained search question → targeted re-retrieve → minimal edit with continuing citation indices. The borrowable core of "OpenScholar corrective RAG".
3. **`max_per_paper` diversity cap** (`open_scholar.py:616-630`) — B5: 15 lines, no deps, prevents single-paper context capture after RRF fusion.
4. **Edit regression guard** (`open_scholar.py:651-655, 689-700`) — J1: >0.9 length-ratio acceptance gate on every self-edit; FAR-Lab revise stage currently trusts edits.
5. **MinHash near-dup + query-echo decontamination** (`deduplication.py:28-90`, `search.py:473-481`) — B5/J1 hygiene for multi-source fusion and metric validity.
6. **Next-chunk retrieval** (`search.py:124`) — B6 fidelity: ship ±1 neighbor chunk with every passage excerpt.
7. **1-shot cited-example demonstration contract** (`instructions.py:80-104`) — C4: model-agnostic way to force inline `[i]` citation behavior; direct input to FAR-Lab prompt templates.
8. **Citation-support Yes/No judge prompt** (`instructions.py:282-301`) — J1: portable support-checking judge scaffold (harness itself in ScholarQABench — flag for a follow-up source report).

## 5. Rejection notes

- **peS2o datastore / Contriever training / FAISS index stack** (`retriever/src/*`, `retriever/contriever/*`): FAR-Lab retrieves via OpenAlex/arXiv/crossref APIs; self-hosting a 200M-embedding index contradicts minimal-sufficient architecture and API-based scope. Mechanism-level ideas (chunk size 256w, flat-IP, shard-merge-by-score) noted only as reference.
- **Model training** (`training/` torchtune tree, reranker/embedding training recipes in README): out of scope by task definition (model-agnostic product).
- **Citation-count priors** (`min_citation`, `norm_cite`, `sort=citationCount:desc` in S2 queries): rejected on scientific grounds for FAR-Lab — biases literature context toward old, highly cited work, undermining recency-sensitive hypothesis generation. The *filter-only-if-enough-remain* pattern (`open_scholar.py:122-126`) is a reasonable safety shape if ever needed.
- **vLLM local inference path, llama3 chat template formatting** (`open_scholar.py:67-99, 224-247`): FAR-Lab is API-based; irrelevant.
- **Word-count cost accounting** (`open_scholar.py:16-35`): inaccurate proxy; FAR-Lab should keep true token accounting.
- **Flask single-flight retrieval service** (`serve_pes2o.py`): only relevant if self-hosting dense retrieval, which FAR-Lab rejects above.
- **Google/you.com site-search scraping + ar5iv HTML parsing**: brittle external surface, licensing/ToS gray zone, and FAR-Lab already has sanctioned APIs; keyword-expansion *pattern* (mechanism #7) survives, the scrapers don't.
