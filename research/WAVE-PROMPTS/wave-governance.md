# Wave-G 最高执行指令 · 项目治理与质量巅峰（收官 Wave，四阶段依序执行）

> 使用方式：在全部前序 Wave 收口、项目任务全部完成后，整份作为 /goal 交给新窗口。共同基线见 `research/WAVE-PROMPTS/_COMMON-BASELINE.md`（粘贴时一并带上）。
> 定位：按世界顶级开源项目的管理规范与思路，对项目做一次全面治理——更有条理、更规范、代码质量最高、性能最优。四个工作包**依用户指定顺序**执行：①文件治理 → ②全码深度评审与修复 → ③开源调研借鉴再优化 → ④核心性能深度优化。

## 〇、接续点

**开启 Wave-G：先读基线与控制面确认前序 Wave 全部收口（completion-gate VERIFIED_READY、frontier ready、无未决 P0/P1），status→IN_PROGRESS、phase=wave-governance。本 Wave 是治理 Wave：一切"清理/修复/优化"都必须留档（决策、清单、before/after 数据），零静默操作。**

## 一、工作包 1：项目文件治理（开源仓库规范化）

1. **全仓清点与分类**：逐文件分类为——核心源码（src/web/eval 脚本/zcode-harness/必要脚本）、测试、必要文档（README/项目宪法与 spec/用户文档）、证据与决策（evidence/、.control/、research/ 注册表与 SCOUT——它们是本项目事实系统，**保留**）、可删项（无引用的过程文档、过期任务汇报、一次性中间产物、错误/废弃文件、重复内容）。分类判定标准：`rg` 全仓引用检查 + README/evidence 索引/控制面引用三查，无任何引用且无未来价值 → 可删。
2. **删除纪律**：先产出完整删除清单（路径+理由+引用核查结果）落 `evidence/W-G/deletion-manifest.md` 并记 DECISIONS，再执行删除；git 历史不重写（红线）；删后全量门禁必须绿。拿不准的单列"待用户裁决"而不是擅自删。
3. **开源发布结构**：按世界顶级开源仓库规范产出仓库结构提案——公开仓库应只含源代码与必要内容（LICENSE/README/必要文档/测试/配置），明确哪些内部工件（控制面、研究底稿、会话产物）不入公开仓库；给出"工作区（全量事实）vs 公开发布（精简视图）"的边界与导出机制提案（大结构移动须保持构建/测试绿，逐项提交）。
4. **卫生项**：.gitignore 完整性（dist/node_modules/.cache/运行数据）；根目录整洁（path-hygiene 绿）；secret-scan 绿；无孤儿文件。

## 二、工作包 2：全码深度评审与质量提升

1. **分模块高并发深审**（每个子 Agent 一个模块：src/domain、src/pipeline 各 stage、src/sources、src/providers、src/persistence、CLI、web/、eval/、zcode-harness/、scripts 与 spikes）：审查维度——正确性缺陷 / 逻辑不严谨 / **未开发完的接口与死代码** / 吞错与空 catch / any 与类型逃逸 / 未 await 的异步 / 可变性违规 / 注入面 / 浅测试与装饰断言 / 命名与一致性 / 文档-代码漂移 / TODO 与 stub 残留。
2. **修复纪律**：根因修复（修数据源头非调用点绕过）；每修一处配回归测试；宪法零容忍项（any/@ts-ignore/空 catch/假实现）零存量；未开发完的接口要么补完（带测试+真实路径验证）要么明确删除并留档，不许"半成品常驻"。
3. **验收**：全量门禁绿（typecheck/lint/vitest/构建）；对修复批次做对抗审计（子 Agent 复审，主 Agent 修根因）；新增测试做 mutation 抽查（注入缺陷必须变红）；评审报告全量落 `evidence/W-G/code-review/`（发现→分级→处置→证据）。
4. 质量标准 = 最高：不只"能用"，而是命名、边界、失败路径、可测性、可读性全部达标；与仓库既有风格一致的惯用写法。

## 三、工作包 3：开源调研与借鉴（针对我们的弱点定向补强）

1. **弱点驱动选题**：以工作包 1/2 的发现 + `eval/north-star.json` 落后指标 + 注册表 B 节缓延项为选题依据，明确"我们弱在哪、要找什么"。
2. **高并发调研**（子 Agent 分线）：①完整开源项目（学习技术架构与思想方式）；②智能体项目（agent 设计与编排思想）；③**Skills/插件类项目**（重点学：工作流程安排、任务调度、设计思想——如何把可复用能力封装为可触发、可组合的工作单元）；④同类科学工具。每项核验存在/活跃度/License，过三重门。
3. **汇总与再优化**：产出 `research/WAVE-G-SCOUT.md`（决策 feed + 反转触发），按 Marginal Value Gate 源码级融合（沿用决策词汇），每项融合带测试+before/after 基准+对抗审计；不采用项如实记录理由。

## 四、工作包 4：核心性能深度优化（最后执行）

1. **测量先行铁律**：先画像后优化——全 run 墙钟、各 stage 耗时分布、模型调用/等待比、sqlite 查询模式与索引命中、工件哈希与 IO、web 构建体积与运行时性能、内存峰值；产出基线画像 `evidence/W-G/perf-baseline.md`。无数据不优化。
2. **优化对象**：核心算法与数据结构（检索去重/融合、BT 迭代、DB 查询与索引、批量操作、缓存机会、web 渲染与 bundle）；每项优化必须 before/after 同口径实测（北极星 run-wall-clock 及相关指标），≥5% 可测改善或消除实测瓶颈才合入，零功能/诚实性回退。
3. **反复迭代**：优化→复测→下一瓶颈，直到边际收益低于阈值并如实记录；性能优化不得弱化可读性与测试。

## 五、诚实与安全警戒（本 Wave 加严）

- 清理≠隐藏：git 历史保留；一切删除留清单与决策记录；拿不准交用户裁决。
- 修复≠变绿表演：禁止弱化测试/校验来"通过"；未开发完接口的处置（补完或删除）必须留档。
- 优化≠注水：性能数字全部实测（命令+退出码+关键输出），before/after 同口径同 seed；禁止选择性汇报。
- 调研结论全部带可验证来源；License 不明=不可复制。
- 收口 DoD：四工作包全部完成 + 北极星账本更新 + 控制面/注册表/记忆同步 + completion-gate 复跑存档 + 全量门禁绿。
