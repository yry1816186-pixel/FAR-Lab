## 一、模块边界（用户定义，逐字生效）

本模块包含全部面向使用者的交互载体，不限于网页前端：
1. **Web 端**：React 应用、HTML5 交互页面、UI 组件、UX 交互逻辑、动画动效；
2. **桌面 GUI 程序**：Windows / Mac / Linux 桌面图形客户端、可视化监控面板、流程状态展示界面；
3. **CLI 交互终端程序**：命令行交互、进度输出、交互式提示符、终端可视化；
4. **全部用户体验相关**：UI 视觉、UX 交互流程、操作反馈、过程可视化、状态监看、结果展示、人工干预操作入口；
5. **多平台兼容**：Windows、Mac、Linux（含无图形服务器版本的有限交互能力）。

**不属于本层**：后端业务逻辑、底层调度引擎（只做它们的状态呈现与干预入口）。

## 二、第一阶段：调研（高并发子 Agent，全部结论带可验证来源）

**调研线 A｜美学与设计规范**（每条取设计 token 层面可执行结论，非泛泛截图）：
- Material 3（含动态取色/层级/动效规范）；Apple HIG（含平台惯例与无障碍）；Microsoft Fluent 2（Windows 11 原生感）；GNOME/KDE HIG（Linux 桌面惯例）；WCAG 2.2 无障碍（对比度/键盘/读屏）；终端/TUI 设计惯例（色彩、密度、渐进披露）；数据可视化最佳实践（科学数据、DAG/流程图、进度与状态的诚实呈现规范）。

**调研线 B｜开源可复用实现**（逐项核验存在性+活跃度+License，走三重门）：
- Web 组件体系：shadcn/ui、Radix UI、Tailwind、TanStack（Table/Query）、Framer Motion(motion)、Recharts/visx/Lightweight-Charts、react-flow（工作流 DAG）、dnd-kit、cmdk（命令面板）、sonner、lucide；
- 桌面框架：Tauri v2（轻量、Rust 壳、复用现有 React）vs Electron（生态成熟）——给出决策矩阵而非默认选型；
- CLI/TUI：ink（React 渲染 CLI，技能栈复用）、clack（交互提示）、commander/yargs、listr2、ora、figures、进度条与 sparkline 方案；参考系（不引依赖只学设计）：ratatui、textual、bubbletea；
- 监控面板参考系：Grafana 面板模式、JupyterLab/Galaxy/KNIME 等科学工作流 UI、开源 agent 产品 UX（codex TUI/claude code/opencode——若 Wave-4 SCOUT 已有 H 组产出则直接接续，勿重研）；
- 中文排版与字体方案（竞赛评审为中文用户）。

**调研线 C｜本项目现状盘点**（主 Agent 亲自做，禁止子 Agent 转述失真）：
- `web/` 代码全量清点：现有页面/组件/状态绑定/交互流/已知 P2/P3 残留（PlanTab provenance 等）；CLI 现有命令面与输出体验（dist/cli）；读 project-spec/policies/PRODUCT_HCI.md、.control/ACCEPTANCE_STATUS.json、W-P1 交付物（若已执行）与 eval/north-star.json 的 hci 指标。

## 三、第一阶段产出：《FAR-Lab 人机交互层设计规划方案》

落盘 `research/WAVE-HCI-DESIGN-PLAN.md`，必须完整覆盖：
1. **产品定义**：目标用户画像（科研使用者/竞赛评审/开发者）、核心任务（Jobs-to-be-done）、成功标准；
2. **核心用户旅程**（端到端）：提出问题 → 监控运行（长任务/失败/暂停各状态）→ 检视证据/假设/计划 → 人工干预（取消/恢复/反馈修订）→ 导出复现 → 结果呈现；
3. **信息架构与导航**（三形态统一的信息模型，与 canonical domain model 术语对齐，不造第二套话术）；
4. **各平台体验蓝图**：Web / 桌面 GUI / CLI 三章，每章含页面/命令清单、状态机呈现、干预入口、动画与反馈规范（明确"何时动、何时静"）；
5. **视觉语言**：设计 token 体系（色/字/距/密度/动效曲线/暗色模式）、美学方向（科学严谨取向，附 2-3 个可选方向供用户选）；
6. **过程可视化与状态监看**：运行管线阶段图、证据/假设/锦标赛状态、进度诚实呈现规范（未知即未知，禁止发明百分比）；
7. **人工干预操作入口全集**：每项干预 × 三平台的可用性与降级路径；
8. **多平台兼容矩阵**：能力 × 平台（含无图形服务器的有限交互——明确 CLI-only 降级形态）；
9. **复用 vs 自建决策表**：每组件标注 采用的开源件+License+理由 / 自建理由，全部过三重门；
10. **无障碍与中文体验**专章；
11. **实施路线图**：分期计划，每期有可验收 DoD 与北极星指标映射（hci-audit-p1=0、核心任务无辅助走查 5/5，可新增 UX 指标但须可真实测量）；
12. **风险与未知**（如实）。

**诚实铁律（本 Wave 加严）**：
- 方案中每个开源件/规范引用均须真实核验（存在、License、活跃度）——禁止编造链接/组件/版本；
- 示意图只能是明确标注的线框/文字描述（ASCII/mermaid/结构说明），**禁止伪造"截图"或声称已存在的界面**；
- 现状盘点必须基于代码实读（file:line），禁止凭印象描述现有功能；
- 方案不承诺未经验证的性能/效果数字；估时给区间并标注不确定性。

## 四、用户审阅门（硬门）
方案完成后：向用户交付方案摘要 + 文件路径，**状态置 waiting_for_user_review 并停止**；用户明确批准（及可能的选择项裁决，如美学方向）后，方可在后续窗口开启第二阶段实施（实施提示词届时按方案内路线图生成）。**未经批准的任何实施代码 = 违规。**
