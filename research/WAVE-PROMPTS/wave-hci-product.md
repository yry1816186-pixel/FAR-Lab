> 使用方式：整份作为 /goal 交给新窗口（建议在全部前序 Wave 收口后执行）。共同基线见 `research/WAVE-PROMPTS/_COMMON-BASELINE.md`（粘贴时一并带上）。

## 〇、接续点

**开启 Wave-PRODUCT 第一阶段：以完整、成熟的产品经理+产品设计师思维，对 FAR-Lab 做全域「设计、考虑、检查」三类工作。设计=新方案；考虑=悬而未决的决策点（带选项与推荐交用户裁决）；检查=对现有实现的全套审计。先高并发调研开源项目、美学规范与同类产品，结合对本项目现状的真实盘点与审计，产出统一《产品全景设计规划方案》交用户审阅。**

## 一、范围（三层定义）

**1. 人机交互层（用户定义，逐字生效，本 Wave 最大章节）**：
- Web 端：React 应用、HTML5 交互页面、UI 组件、UX 交互逻辑、动画动效；
- 桌面 GUI 程序：Windows / Mac / Linux 桌面图形客户端、可视化监控面板、流程状态展示界面；
- CLI 交互终端程序：命令行交互、进度输出、交互式提示符、终端可视化；
- 全部用户体验相关：UI 视觉、UX 交互流程、操作反馈、过程可视化、状态监看、结果展示、人工干预操作入口；
- 多平台兼容：Windows、Mac、Linux（含无图形服务器版本的有限交互能力）。

**2. 产品全景层（本次扩展，同样需要设计/考虑/检查）**：
- 产品定位与叙事：用户画像与 JTBD 细化、面向竞赛评审的产品故事线、命名与术语体系（全表面统一，对齐 canonical domain model，不造第二套话术）、品牌视觉（标识/色彩/字体身份）；
- 信任与科学呈现：不确定性/证据边界/诚实弃权的呈现设计（让"诚实"成为产品强项）、live 回执与溯源的用户可验证体验、复现包（far verify）的分享与核验体验；
- 交付物设计：技术方案 PDF 的文档与信息设计（图表规范、数字溯源版式）、≤10 分钟演示视频的脚本与分镜设计、可调用测试 API 的接口设计；
- 运维与配置体验：安装与首启引导、密钥/凭证管理体验（DASHSCOPE/OPENALEX 等的引导-验证-提示闭环）、升级与数据迁移、备份恢复、运行历史与工件的数据管理（增长/清理/导出导入）、健康检查与自助诊断、部署形态决策（单机本地 vs 服务器多用户 vs 无头）；
- 模型面用户可见性：模型路由透明度、成本与配额的可视化（token 用量/预算守护）、限流与重试的用户感知；
- 可靠性用户面：崩溃/冻结的检测与恢复体验、resume 与部分结果的呈现、失败任务的引导下一步；
- 文档体系：README/用户指南/API 文档/开发者文档/架构文档/教程的结构、风格与真实性统一。

**3. 不属于本 Wave**：后端业务逻辑与底层调度引擎的内部实现（前序 Wave 负责）；但它们的一切状态呈现与干预入口属于本 Wave。

## 二、第一阶段调研（高并发子 Agent，全部结论带可验证来源）

**线 A｜美学与设计规范**：Material 3 / Apple HIG / Fluent 2 / GNOME-KDE HIG / WCAG 2.2（Web+终端可访问性）/ 终端 TUI 设计惯例 / 数据可视化最佳实践（科学数据、DAG 流程图、进度的诚实呈现规范）。
**线 B｜开源可复用实现**（逐项核验存在+活跃度+License，过三重门）：Web 组件体系（shadcn/ui、Radix、Tailwind、TanStack、motion、Recharts/visx、react-flow、dnd-kit、cmdk、sonner、lucide）；桌面框架（Tauri v2 vs Electron 决策矩阵）；CLI/TUI（ink、clack、listr2、ora 等；ratatui/textual/bubbletea 仅作参考系）；中文排版与字体方案。
**线 C｜现状盘点与审计（主 Agent 亲自，禁止转述失真）**：web/ 与 dist/cli 全量实读（file:line）；配置面（env/首启）；文档现状；导出/复现体验现状；读 PRODUCT_HCI.md、ACCEPTANCE_STATUS、前序 Wave 的 SCOUT（W4 H 组 UX 产出直接接续勿重研）、W-P1 交付物、eval/north-star.json。
**线 D｜信任与科学呈现专项**：不确定性可视化与 provenance UI 的研究与开源案例（科学工具如何呈现证据强度/局限）、citation/回执 UI、空状态与弃权状态的优秀范式。
**线 E｜文档与信息设计**：优秀技术文档/架构文档/README 范式、图表规范（mermaid/架构图最佳实践）、错误信息设计指南。
**线 F｜同类产品全景对标**：AI-Scientist 类产品与其他科研工具如何定位/叙事/演示/定价（产品层对标表：我们差异化在哪、评审会看到什么差异）。

## 三、第一阶段产出：《FAR-Lab 产品全景设计规划方案》

落盘 `research/WAVE-PRODUCT-DESIGN-PLAN.md`，每节标注【设计/决策/检查结果】三类型之一；必须覆盖：
1. 产品定义：用户画像、JTBD、成功标准、竞争定位（线 F 结论）；【设计】
2. 产品叙事与品牌：故事线、命名术语表、品牌视觉身份（2-3 方向供选）；【设计+决策】
3. 核心用户旅程（端到端）：提问→监控（长任务/失败/暂停/冻结各状态）→检视证据/假设/计划/锦标赛→人工干预（取消/恢复/反馈修订）→导出复现→结果呈现；【设计】
4. 信息架构与导航（三形态统一信息模型）；【设计】
5. Web 体验蓝图（页面清单/状态机呈现/干预入口/动画规范）；【设计】
6. 桌面 GUI 蓝图（框架决策矩阵+监控面板+流程状态界面）；【设计+决策】
7. CLI 体验蓝图（命令面/进度/交互提示符/终端可视化）；【设计】
8. 视觉语言：设计 token 体系（色/字/距/密度/动效曲线/暗色）、美学方向 2-3 选；【设计+决策】
9. 过程可视化与状态监看规范（诚实进度：未知即未知，禁止发明百分比）；【设计】
10. 人工干预操作入口全集（每干预 × 三平台可用性与降级）；【设计】
11. 信任与科学呈现（不确定性/溯源/回执/复现包体验）；【设计】
12. 交付物设计（PDF 文档设计/演示视频脚本/测试 API 接口）；【设计】
13. 运维与配置体验（首启/密钥/迁移/备份/数据管理/诊断/部署形态决策）；【设计+决策】
14. 多平台兼容矩阵（含无头降级形态）；【设计】
15. 文档体系规划；【设计】
16. **检查结果汇总**：八项审计全量发现（见第四节），P0-P3 分级 + 修复建议并入实施路线图；【检查】
17. 复用 vs 自建决策表（每组件：开源件+License+理由 / 自建理由，过三重门）；【设计】
18. 实施路线图（分期，每期 DoD+北极星映射）与风险未知（如实）。【设计】

**诚实铁律（加严）**：引用均真实核验（存在/License/活跃度），禁止编造链接组件版本；示意图只能是明确标注的线框/文字/mermaid，禁止伪造截图或声称不存在的界面；现状盘点基于代码实读 file:line；检查结论必须可复现（命令/位置）；不承诺未验证数字；禁止任何表演演示性内容。

## 四、检查层：八项审计（第一阶段内完成，逐项独立报告并入方案第 16 节）

1. 一致性审计：跨 Web/CLI/文档/导出的术语与状态命名对齐（对照 domain model）；2. 状态真值审计：每个显示状态/控件↔真实系统状态映射（假控件/假进度零容忍）；3. 错误信息质量审计（可操作性/根因可见/下一步引导）；4. 无障碍审计（Web WCAG 2.2 AA + 终端可访问性）；5. 中文与排版审计（术语统一/字体/标点/混排）；6. 空状态与首次引导审计；7. 文档真实性审计（文档宣称↔实现实况逐条对账）；8. 死功能/未绑定/装饰元素审计。每项产出 P0-P3 分级清单（file:line 或复现命令）。

## 五、用户审阅门（硬门）

方案完成：交付摘要+路径，status→waiting_for_user_review 并停止。用户明确批准（含各决策点裁决：美学方向/桌面框架/部署形态等）后，方可在后续窗口开启第二阶段实施（实施提示词按方案路线图生成）。**未经批准的任何实施代码 = 违规。**
