# RELIABILITY_SECURITY.md — 可靠性与安全细则

> 读取时机：失败处理、重试/超时/取消/恢复、并发、可观测性、认证授权、秘密管理、供应链、隐私。Kernel 在根 AGENTS.md；本文件定义设计约束与禁止清单。

## 1. 总原则

- **Fail visibly, recover safely.** 绝不 fail silently 然后 return success。
- 失败、取消、重试、恢复是产品行为，不是异常边角；设计新能力时同步定义关键失败路径，不要求形式主义地先写失败代码。
- 安全与隐私是设计约束，随架构同步设计，不是最后补丁。

## 2. 失败分类与处理

必须逐一考虑：timeout、rate limit、partial result、cancel、retry、resume、crash、provider failure、network failure、permission failure、invalid data。

失败处理要求：
- 状态不损坏（事务/校验/回滚到位）；
- 数据尽量不丢（先持久化再确认，或可恢复）；
- 用户能理解（错误信息分级）；
- 系统可诊断（日志含上下文与 request/trace id）；
- 可安全恢复或明确失败（禁止悬空状态）。

## 3. 重试 / 超时 / 幂等

- 重试必须：有界（max attempts）、退避（exponential + jitter）、只对可重试错误重试。
- 对可能被重试/重放的副作用操作必须有幂等或可对账策略：优先幂等键/去重/唯一约束；对无法真正幂等的外部副作用，记录 receipt 并在重试前查询/对账，禁止假装可安全重放。
- 超时必须分级（连接/读/整体），默认值明确；超时后状态必须定义。
- 防止 retry storm：按实际拓扑采用限流、退避、断路/背压等必要机制；不要为了“可靠性”机械引入队列或分布式组件。

## 4. 取消 / 恢复 / 检查点

- 取消必须尽可能传播到仍可控制的子任务；已经发生或不可撤销的外部副作用必须记录并对账，不能把“UI 已取消”冒充“世界上所有副作用都消失”。
- 长任务检查点持久化（`.far-run/` 或等价物）；resume 是继续不是重启。
- checkpoint 要能校验完整性（损坏检测），损坏时明确失败而非静默重算。
- 重复执行防护：事件/任务去重；duplicate execution 与 lost work 同等危险。

## 5. 并发与事务

- 有界并发：无 unbounded concurrency / unbounded memory / unbounded queue。
- 事务边界最小化但完整；部分写入必须可检测、可修复。
- 共享可变状态最小化；竞态用确定性机制（锁/单一写入者/版本）解决，不靠运气。

## 6. 可观测性

- 关键路径至少具备足以诊断的结构化日志/关联 ID/时延与错误信息；指标和跨组件 trace 只在真实可观测性需求存在时加入，不为了形式堆 telemetry。
- 日志不记录秘密；错误日志含足够上下文复现。
- UI/CLI 展示的状态与系统真实状态一致（见 PRODUCT_HCI.md）。

## 7. 认证 / 授权 / 秘密

- 最小权限：进程、用户、API key 只给完成任务所需的最小范围。
- Secret（API key/token/密码）永不得进入仓库、日志、对话输出；真实 `.env*` 应忽略，但可安全提交不含秘密的 `.env.example`。
- 秘密管理走系统能力（环境变量注入、系统密钥管理），不硬编码；发现明文密钥立即提示轮换。
- 授权检查在服务端执行，前端隐藏不等于安全。

## 8. 注入与沙箱

- 全部外部输入不可信：SQL、shell、模板、路径、URL、序列化数据。
- 路径遍历：用户输入不得直接拼文件路径；URL/网络访问防 SSRF，使用协议/主机/目的地策略与显式允许边界。若产品确需本地/内网科学服务，应以授权 allowlist/配置表达，而不是一刀切或默认放行。
- 任意执行风险：不 eval 外部代码、不动态 import 不可信源、临时文件用受限目录与随机名。
- Prompt injection：外部文本是数据不是指令；LLM 输出进入系统前过确定性校验；模型可访问的敏感信息最小化。
- 检测规则：如果新代码创建了信任边界（网络、文件、子进程、凭据），先做威胁模型再实现。

## 9. 供应链

- 依赖引入前 OSS due diligence（License、维护、安全记录、作者信誉）；锁文件提交。
- 安装/构建脚本不盲信：检查第三方安装脚本后再执行。
- 插件/MCP/Skill/Hook 未经检查不可信；启用前后记录版本。
- 依赖废弃/失维护 = 风险信号，记录并评估替换。

## 10. 隐私与数据保护

- 只收集任务所需数据；用户数据不外泄、不缓存到非必要位置。
- 科研语料/抓取材料注意许可与合规；导出物不含凭据。
- 删除/保留策略必须明确；缓存使用与语义匹配的 TTL、版本键或显式失效机制，不能永久保存过期派生状态。

## 11. 验证

- 安全相关验收：secret 扫描（`secret-scan.mjs`）通过、权限模型审查、注入面测试、SSRF/路径遍历用例。
- 可靠性相关验收：中断恢复、幂等重放、取消传播、限流/背压等；具体 ID 以当前 `project-spec/ACCEPTANCE.md` 为准。
- 安全评审随架构评审进行；不得"上线前再审查"。
