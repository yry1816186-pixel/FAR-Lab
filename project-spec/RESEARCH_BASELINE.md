# RESEARCH_BASELINE.md — Decision-Oriented Research Baseline

## 1. Authority

This file is a compact routing baseline for construction. Fresh primary-source/runtime evidence for the current decision outranks it. The large pre-research corpus is preserved cold at `research/reference/FARLAB_PRE_RESEARCH_INTELLIGENCE_BASELINE.md`; do **not** auto-load that file into normal ZCode context.

## 2. What is already clear enough to build around

- FAR-Lab’s differentiated core is not generic retrieval or agent orchestration; it is the integration of **evidence truth + competing hypotheses + counter-evidence/uncertainty + falsifiability/testability + executable planning + causal revision + provenance/reproducibility** into one researcher workflow.
- Durable state/recovery is required because the product runs multi-stage external/model/tool work; however an external durable-workflow framework is not justified until the simple persisted state machine fails a real requirement.
- Scientific correctness needs a separate evaluation plane from software correctness.
- Product/HCI is part of scientific usefulness: researchers must inspect evidence, compare hypotheses, control long runs, understand failures and trace revisions.
- Competition release requires a first-class live path on the officially required model route under the current official rule; the provider abstraction is the core and supports all models worldwide.

## 3. Candidate landscape to revisit only when decision-relevant

The cold corpus contains serious leads across:
- durable workflow/effects: Temporal, DBOS, Restate and adjacent systems;
- scientific provenance/reproducibility: AiiDA, RO-Crate, OpenLineage, Sigstore/in-toto, DataLad/lakeFS/Dolt;
- evidence/search: OpenAlex, Crossref, OpenCitations, scholarly/full-text/domain sources, hybrid retrieval/reranking;
- scientific computing: Jupyter/marimo, PETSc/Kokkos, Stan/ArviZ/DoWhy/BoTorch and domain tool ecosystems;
- HCI/workbench: JupyterLab, marimo, Theia, Quarto and scientific visualization patterns;
- security/policy/formal methods: OPA/Cedar/OpenFGA/SpiceDB, TLA+/Apalache, sandbox/WASM/Firecracker families;
- HPC/remote: Slurm/Flux and related schedulers;
- interoperability/protocols: MCP and other tool/agent protocols.

These are **search seeds, not approved dependencies**. Exact releases/licenses/maintenance/performance must be rechecked when a real requirement puts a candidate on the critical path.

## 4. Highest-value R1 research obligations

1. Provider structured-output/tool-call reliability on the intended schemas and failure modes.
2. Real citation/source resolution and claim-source alignment, including what metadata/abstract/full text/domain data is actually available.
3. Hypothesis diversity/dedup and falsifiability review quality on representative questions.
4. Research-plan executability representation and deterministic checks without pseudo-scientific rigidity.
5. Persistence/recovery/cancel/idempotency behavior across model/source/tool failures.
6. Web/CLI information architecture for high-density evidence/hypothesis/plan/provenance workflows.
7. Runnable strong baselines and an evaluation protocol that does not reward the system by construction.
8. Performance/cost/fan-out measurements before adopting distributed/queue/vector/graph infrastructure.

## 5. Research protocol

`decision/question -> broad capability search -> primary-source verification -> serious candidate inspection -> spike/run if it can change architecture -> compare strongest alternative + BUILD -> decision + reversal trigger`.

Stop at decision saturation. Preserve contrary evidence and rejected candidates only when they explain an important decision.
