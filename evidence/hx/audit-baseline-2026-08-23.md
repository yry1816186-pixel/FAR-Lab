# HX 重构基线审计 — 以第一次使用的科研人员身份实测

日期：2026-08-23 · 分支：build/hx-reconstruction · 数据：真实持久化运行（run_jpktce50q7wqc68rkg64ztm3me 等 52 项）
方法：fresh 构建（root dist + web/dist）+ `node scripts/serve.mjs` + Playwright 全程实测（截图：hx-audit-01/02）
约束遵守：全程只读既有真实数据，未触发任何真实模型/检索 API 调用。

## A. 值得保留的资产（不要推倒的部分）

1. **术语层已是科研语言**：研究库/假设/证据/计划与实验/修订史/核验与导出——六区 IA 骨架方向正确。
2. **研究结论卡**：结论先行 + BT 分数 + "决策辅助，非客观真值"不确定性声明——这是正确的科研诚实表达。
3. **范围界定 in/out 列表、深度列（仅元数据/摘要）、核验状态**：语义正确。
4. **渐进披露已有雏形**：运行元信息折叠、对局明细折叠、维度评分展开。
5. **失败/终态按钮的诚实禁用 + 原因说明**。
6. URL hash 路由（#run/:id/:tab）、命令面板、i18n 中英、主题切换、快捷键提示。

## B. 核心病灶（重构靶点，按伤害排序）

### B1. 入口仍是"管线受理表单"，不是 Research Composer
- 首屏 = 一个必填 textarea + 提交按钮。无拖放区（仅一行小字"或拖入 PDF / .bib / .ris / .txt / .md"）、无上传状态/预览/失败重试体验、无 URL/DOI 添加入口、无 AI 澄清对话。
- "工作台状态：正常 · 模型路由 1/2 就绪" —— 内部概念泄漏到第一屏。
- "提交后可在左侧任务列表跟踪全流程" —— 教用户理解内部机制。

### B2. 活动流 = 工程师遥测，不是"AI 在做什么/为什么"
- "研究动态真实事件流"直接展示：`模型调用 · glm-4.6 · 15779ms · 研究计划`、sha256 哈希、`declaredEvidenceLevel=replay`、运行状态变更。
- 科研人员想要的是叙事（"检索了 14 个文献源 → 核验 12 个 → 其中 4 篇拿到摘要 → 生成了 10 组假设…"）；遥测应收纳进可展开的"技术轨迹"层。

### B3. 内部 ID 与评分公式裸奔
- 页头直接显示 `run_jpktce50q7wqc68rkg64ztm3me`；计划页正文出现 `clm_srbpr7y4pehv8cvs79p5qw4j24`、`hyp_gb5jyqt4jk0w0mq56k7mwsga4r`。
- "Composite 0.7444 = weighted average of valid dimensions (fixed weights evidence_grounding 0.2, falsifiability 0.15…)" 公式原文进表格单元格。
- "全部 10 个假设" vs "排序代表（6）" 计数不一致无解释。

### B4. 假设对比 = 纯表格 + 中英混排警示
- 评分对照/锦标赛两张大表并列；长英文假设陈述截断成链接；BT 强度 5.818 vs 0.175 vs 0.006 的量纲不直观。
- 长警示段（"Pairwise verdicts are uncalibrated…"）整段英文出现在中文 UI。
- 无并列对比画布、无可视化证据平衡。

### B5. 首屏噪音与状态健壮性
- 侧栏首屏即见"需注意 32"（历史失败堆积），首次用户会被吓到；时间戳秒级精度（2026/08/23 00:13:53）。
- SSE 流断开（ERR_CONNECTION_RESET）UI 无任何可见反馈/重连提示。
- "研究已已完成"重复字。

### B6. 视觉系统
- 图标大量使用文本字形（✓ ✗ ▲ — ≫ ↳ ●）充当 icon 体系；无产品级 iconography/motion；价值主张三条的视觉权重与表单同级。
- 无 onboarding 叙事（"这是什么/第一步做什么"只靠一行 tagline + 三条静态列表）。

## C. 结论

骨架（域模型、六区 IA、诚实状态、渐进披露雏形、i18n/路由/命令面板）值得保留并升级；
交互范式（受理表单+事件遥测+表格海）是重构对象。
下一步 = Wave2 设计综合：Research Operating Environment 的 IA + Composer + 活动叙事层 + 结果工作区，复用映射待三路 scout 报告返回后定稿。
