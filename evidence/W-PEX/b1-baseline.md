## 3. B1 热修（P0/P1，全部 GUI 验证）

- **F-01 (P0) 创建后选中劫持**：`onCreated` 设置新 run 选中后，守卫效应在**旧 runs 列表**上命中（新 run 尚未入列）→ `setSelectedRunId(runs[0])` 静默跳到无关研究，hash URL 一并污染。修复：①onCreated 置 runsLoading=true 挂起守卫；②守卫命中改为诚实取消选中（null）——系统无删除 API，静默换研究永无正当性。验证：第二个真实 run（run_751xw3 神经科学）创建后 URL+主区=新 run（evidence: 本文件+提交）。
- **F-02 (P0) 事件流可见性死亡**：事件流只靠可见性门控轮询，IAB/后台标签 `visibilityState=hidden` 下永远"暂无事件"（API 有 59 条）。修复：选中 run 即直拉一次（App.tsx）。
- **F-03 (P0) 轮询首拉可见性门控**：runs/健康同病（首开侧栏卡"加载中…"直到手动刷新）。修复：usePolling 首次执行不受可见性门控（门控意图=防隐藏标签 churn，非扣住首屏数据）。验证：重载后侧栏即载入、面板恢复 19 命令。
- **F-04 (P1) abort 误分类 bad_json**：run/tab 切换中止中的 fetch，截断 body 解析失败被报为"API 返回了无法解析的 JSON"。修复：client.ts 解析失败时 signal.aborted → 还原 AbortError。验证：代码路径修复+复现场景（深链切换）不再出错误框（curl 侧两端点 JSON 恒合法）。
