# 自定义模型配置（Custom Model Configuration）端到端实现

## 目标

产品内提供完整的自定义模型配置能力：用户可添加任意 **OpenAI 兼容 / Anthropic 兼容** 端点（baseUrl + apiKey + modelId，覆盖 OpenAI、Anthropic、GLM、Qwen、Gemini 兼容端点、vLLM/Ollama 本地模型等世界所有模型服务），设为默认或按 run 选择，流水线真实使用该配置调用，溯源 receipt 记录实际 provider/model。

**生效优先级**：`run.providerConfigId`（建 run 时手选）> `active` 全局默认配置 > 现有 env 链（`FARLAB_MODEL_PROVIDER`，竞赛强制路由与自动化测试路径原样保留，一行不动）。

**Key 策略（业界成熟做法）**：明文仅存本地 SQLite（.far-run/ 已 gitignored，服务只绑 127.0.0.1，与现有 .far-run/secrets.env 威胁模型一致）；API 响应 / UI / 日志 / 测试 fixtures 永不出现明文，只返回尾 4 位掩码。

## 后端

### 1. Domain 层
- **新 `src/domain/model-config.ts`**：`ProviderWireProtocol = z.enum(['openai','anthropic'])`；`ModelProviderConfig` zod schema：`id`（newId 'mcfg' 前缀）、`label`、`wire`、`baseUrl`（z.string().url()）、`modelId`、`apiKey`、`createdAt/updatedAt`。
- **`src/domain/run.ts`**：`ResearchRun` 加 `providerConfigId: z.string().optional()`（向后兼容，旧 run doc 照常 parse）；`src/domain/index.ts` 导出新 schema。

### 2. Provider 层
- **新 `src/providers/custom.ts`**：`createCustomProvider(cfg, opts?)` —— 泛化 zai/dashscope 薄包装，内部走现有 `runOpenAICompatStructuredCall()`（传输层已全参数化，零新传输代码）：
  - `name: 'custom:<configId>'`（receipt.modelCall.provider 稳定溯源）
  - 空 key → `authFailClosedResult`（与 zai 相同 fail-closed 纪律）
  - `wire='anthropic'` → strip jsonSchema（同 zai 适配）；`wire='openai'` → 原样
  - 另导出 `missingConfigProvider(configId)`：配置被删后的 fail-closed provider（auth_error），**绝不静默回落 env**（可复现性优先）
- `LIVE_PROVIDER_NAMES` / `getProvider()` 闭集不动（custom 是独立构造路径，不进注册表）。

### 3. 存储层（`src/persistence/store.ts`）
- `KIND_SCHEMAS` 加 `model_config`（无 runId 字段 → 自动落 `__none__`，`listObjects('model_config','__none__')` 即全局列表）。
- 加 `getMeta/setMeta(key, value)`（meta 表已存在，Store 尚未暴露）；active 配置 id 存 `meta['activeModelConfigId']`。
- `createRun(question, opts?: { providerConfigId?: string })`。

### 4. 生效链路
- `OrchestratorDeps` 加 `providerFor?: (run: ResearchRun) => ModelProvider | null`；`makeContext` 用 `providerFor?.(run) ?? deps.provider`。
- `src/app/composition.ts` 装配 resolver（新函数，按上述三级优先级）：每次 makeContext 现读 store 构造 provider（本地 SQLite 读，零缓存天然一致——改 key/模型后下一 stage 即生效，receipt 如实记录）。
- 悬空引用（run 指向已删配置）→ `missingConfigProvider` fail-closed。

### 5. API 路由（`src/server/api.ts`，沿用现有手写 segment 风格与错误信封）
- `GET /api/v1/model-configs` → `{ configs: [{id,label,wire,baseUrl,modelId,apiKeyMasked,active,createdAt,updatedAt}], envDefault: {name,modelId,liveReady} }`
- `POST /api/v1/model-configs` `{label,wire,baseUrl,modelId,apiKey}` → 201（zod 校验）
- `PUT /api/v1/model-configs/:id` → 全量更新；body **不含** apiKey 字段=保留原值，含=替换
- `DELETE /api/v1/model-configs/:id` → 删除；若为 active 同时清除 active
- `PUT /api/v1/model-configs/active` `{id: string|null}` → 设/清全局默认（校验存在）
- `POST /api/v1/model-configs/test` `{configId?, wire, baseUrl, modelId, apiKey?}` → 发一次 tiny 真实调用（maxTokens≤16，'{"ok":true}' 契约）验证连通性；configId+无 apiKey 时服务端从 store 取 key；返回 `{ok, latencyMs, modelId?, error?: {kind,message,httpStatus?}}`，错误走现有分类（auth_error/timeout/rate_limited/...）。**一次调用即停**（Key 配额纪律）
- `POST /api/v1/runs` body 加可选 `providerConfigId`（校验存在，否则 404）

## 前端

- **`web/src/api/types.ts` + `endpoints.ts`**：`ModelConfigSummary` 类型 + list/create/update/remove/setActive/test 端点函数；`createRun` 扩展可选 `providerConfigId`。
- **新 `web/src/hooks/useModelConfigs.ts`**：CRUD + active + test 状态管理（参照 useCreateRun 模式）。
- **新 `web/src/components/SettingsPanel.tsx`**（modal overlay，参照 CommandPalette overlay + NewRunForm 表单模式）：
  - 列表卡片：label、wire badge、modelId、baseUrl、masked key、active 标记；操作：设为/取消默认、测试（spinner → ok badge / 错误文案）、编辑、删除（二次确认）
  - 新建/编辑表单：label、wire select、baseUrl、modelId、apiKey（password input；编辑态留空=保留）；测试连接按钮（保存前可测）
  - preset 快捷填充：OpenAI 兼容 / Anthropic 兼容 / 智谱 GLM / 阿里百炼 / Ollama 本地（仅填 baseUrl 默认值）
- **入口**：App header 右侧齿轮按钮 + CommandPalette 加"打开设置"命令。
- **NewRunForm** 高级选项（details 折叠区）加"模型配置" select：`环境默认（zai · glm-4.6）` + 各自定义配置。
- **i18n**：`settings.*` 词条（zh 为 source of truth + en 1:1，web-i18n-keys.test.ts 自动校验完整性）。
- **styles.css**：`settings-*` block，复用现有 token（--surface/--form-border/--sp-*/--radius-s/btn--primary/field-label/field-error），少量新增。
