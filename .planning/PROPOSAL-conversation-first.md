# PROPOSAL: 对话优先的研究流程（Conversation-First Research Flow）

状态：**已批准并落地 Slice 1**（2026-08-23 用户指示"选最好、最智能的方案"；后端对话实体/多轮 API/启动研究桥接 + Web 对话视图/侧栏对话列表/首页流程反转均已上线，60/60 测试绿）
日期：2026-08-23
动因：用户实测反馈——「真实科研流程是思维碰撞、逐步对话、Agent 引导头脑风暴，最终才开始假设。现在的『一句话直接跑管线』根本上是错的。」

## 1. 问题（现状 vs 真实科研流程）

现状：Composer 输入一个问题（可附材料）→ 立刻启动管线 → 检索/假设/计划。
真实科研：研究者先带着**模糊的想法 + 一堆材料**，与同事/导师反复讨论——澄清概念、碰撞机制猜想、发现被忽略的角度——**逐步收敛**出值得检验的研究问题，然后才进入文献检索与假设构造。

PLAN-hx-reconstruction.md 早已预埋此方向（「AI 澄清：提交后进入澄清对话而非直接起跑——仅在后端具备真实能力后接线，不伪造聊天」），当时推迟。本提案把它升格为主流程。

## 2. 目标流程

```
┌─ 对话（新的主入口）──────────────────────────────┐
│ 研究者：想法草稿 + 材料（PDF/BibTeX/Zotero/链接/文件夹） │
│    ↕ 多轮                                                        │
│ Agent：引导提问（范围/变量/机制）· 头脑风暴（对立假设、       │
│        反例方向、跨领域类比）· 阶段小结 · 提出候选研究问题     │
│ 研究者：回答、反驳、追问、补充材料                                │
└──────────────┬───────────────────────────────┘
               ↓ 「以此启动研究」（研究者选中/编辑候选问题）
┌─ 研究（现有管线，不变）─────────────────────────┐
│ run 创建时携带：凝结的问题 + 全部材料 + 对话收敛摘要          │
│ 检索 → 证据 → 假设 → 排位 → 计划 → 报告（现有能力）          │
└──────────────┬───────────────────────────────┘
               ↓ 结果回投对话（Slice 2）
        研究者在对话中讨论结果 → 修正 → 再启动新一轮研究（1 对话 → n 研究）
```

## 3. 设计原则（不可妥协）

1. **不伪造聊天**：每条 Agent 回复都是真实模型调用，收据入账（usage ledger 已有）；模型不可用时对话界面如实显示不可用，不发假消息。
2. **对话是一等持久实体**：与 run 同级（store 表 + append-only 事件），刷新/重启不丢；侧栏从「我的研究」改为「我的对话」（研究列表保留为对话的下钻视图）。
3. **材料链完全复用**：对话内附件 = 现有 seeds 基建（PDF 抽取/BibTeX·RIS/Zotero 文库/批量链接，上限 50），启动研究时原样继承。
4. **收敛是显式动作**：Agent 可提出候选研究问题（结构化卡片），但「启动研究」永远由研究者点击——Agent 不代替研究者决策。
5. **对话上下文有预算**：复用 agent kernel 的 compaction（长对话压缩），控制每轮成本。
6. **模型路由跟随当前选择**（AI 模型菜单已就绪）。

## 4. 技术映射

| 需要 | 现状 | 动作 |
|---|---|---|
| 对话实体/持久化 | 无 | store 新表 conversations + conversation_events（append-only，与 runs 同构） |
| 多轮对话端点 | 无 | POST /api/v1/conversations（建）；GET /:id（读）；POST /:id/messages（研究者发言 → 返回 Agent 回复）；SSE /:id/stream（Slice 2 流式） |
| Agent 回复生成 | agent kernel（src/agent/）已有循环/预算/收据 | Slice 1 用轻路径：单次结构化模型调用（引导型 system prompt + 对话历史 + 材料摘要 + 候选问题 schema），不入工具循环；Slice 3 升级为带工具的 agent 会话（文献预检等） |
| 材料 | seeds 链完整 | 对话消息可携带 seeds；启动研究时透传 |
| run 桥接 | createRun(text, seeds) | 扩展可选 conversationId + 收敛摘要；run 详情显示来源对话 |
| Web UI | Composer 一锤定音 | 新对话视图（chat 流 + 附件托盘 + 候选问题卡片 + 「启动研究」）；Composer 成为对话的第一条消息输入 |
| 侧栏 | 「我的研究」run 列表 | 「我的对话」列表（进行中/已凝结）；对话详情内挂其研究列表 |

## 5. 分期

- **Slice 1（批准后首先做，可独立交付）**：Conversation 实体 + 多轮消息 API（非流式，回合制）+ Web 对话视图 + 侧栏对话列表 + 「凝结问题 → 启动研究」桥接（带材料+摘要）。离线 stub provider 全链测试。
- **Slice 2**：结果回投对话（run 完成通知 + 结果摘要进对话继续讨论）；SSE 流式回复；文件夹批量材料。
- **Slice 3**：工具化对话（agent kernel 接管：对话中实时文献预检、材料内检索、对立假设自动查反例）。

## 6. 成本与风险（诚实说明）

- 每轮 Agent 回复 = 一次真实模型调用（费用与延迟随轮数增长）；compaction 控制上下文长度。实现期全部用 stub provider 离线测试（遵守 no-live-API 纪律），真实对话体验由你实测。
- 与兄弟会话的 HX6 TUI（终端交互 composer）方向一致不冲突：对话能力在 service 层，两端共用。
- 侧栏信息架构变更（研究列表降为对话下钻）是可见的产品决策点，需要你确认。
